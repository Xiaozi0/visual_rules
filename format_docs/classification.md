## 主轴优化：reasoning_type_primary (推理内核)

> **优化原则**：明确“算法执行（Algorithmic）”、“约束求解（Constraint）”与“博弈规划（Planning）”的边界。
- **`algorithmic` (算法执行)**
    - **定义**：要求模型模拟计算机标准算法的执行过程。任务通常有确定的单向步骤。
    - **典型场景**：图的拓扑遍历（BFS/DFS）、最短路径寻找、连通块计数、字符串/序列操作（如逆序、替换）。
- **`deductive` (演绎推理)**
    - **定义**：从已知的一般性原理、定理或前提出发，通过严密的逻辑步步推导，得出必然性结论（由因导果）。
    - **典型场景**：骑士与无赖问题（真假话判断）、扫雷、一阶逻辑推理、三段论判定。

- **`inductive` (归纳发现)**
    
    - **定义**：从局部或零散的视觉观测中发现潜在的底层宏观规律、趋势或模式（由果导因）。
        
    - **典型场景**：ARC（抽象推理基准）、Raven 瑞文矩阵、Bongard 邦加德问题、序列找规律补全。
        
- **`analogical` (类比映射)**
    
    - **定义**：将一个领域的结构或关系映射到另一个领域（$A : B :: C : D$）。
        
    - **典型场景**：视觉概念类比、几何图形变换类比（如“小圆在大圆内”类比到“小方在大方内”）。
        
- **`constraint_satisfaction` (约束求解)**
    
    - **定义**：在一组相互制约的静态条件/规则限制下，寻找满足所有条件的全局解。
        
    - **典型场景**：数独（Sudoku）、数谜（Kakuro）、图着色问题、N 皇后问题、数织（Nonogram）。
        
- **`spatial` (空间几何推理)**
    
    - **定义**：对物体的三维空间结构、位置、朝向以及拓扑变换进行心理旋转、组合或解构。
        
    - **典型场景**：三维心理旋转、正方体展开图折叠、空间透视、截面判定。
        
- **`numerical` (数值与定量计算)**
    
    - **定义**：涉及计数、代数方程、几何面积体积、离散数学或者数统图标的量化计算。
        
    - **典型场景**：文氏图集合计数、几何图形面积计算、算式解析、图表趋势定量计算。
        
- **`simulation` (状态机与动力学演化)**
    
    - **定义**：根据给定的离散/确定性时间步长规则，推演系统在未来数个时间步（Time Steps）后的状态。
        
    - **典型场景**：康威生命游戏（Cellular Automata）、符号状态机跳转、网格流体扩散模拟。
        
- **`mechanical_physical` (物理规律与机械推理)**
    
    - **定义**：基于真实世界的物理定律（重力、力矩、碰撞、摩擦力、杠杆原理）进行定性或半定量推理。
        
    - **典型场景**：齿轮传动方向判定、天平/杠杆平衡、小球碰撞轨迹预测、滑轮组受力分析。
        
- **`game_rule_planning` (博弈与多步规划)**
    
    - **定义**：在动态、对抗性或目标导向的环境中，进行多步的状态空间搜索，以最大化收益或达成特定目标。
        
    - **典型场景**：推箱子（Sokoban）、汉诺塔、四子棋/围棋落子策略、迷宫全局路径规划。
        

## 副轴优化：visual_type_primary (视觉模态表现)

> **优化原则**：由于你需要进行图像渲染或指导大模型理解，副轴应当直接对应“图像的几何拓扑结构”和“渲染引擎的类型”。

- **`grid_board` (离散网格/棋盘)**
    
    - **特点**：由二维像素状、正方形或六边形单元格紧密平铺构成的阵列，颜色或符号填在格内。
        
    - **对应渲染**：Pixel array, Pygame grid.
        
- **`table_matrix` (结构化数据表格)**
    
    - **特点**：带有明确行列语义、用于承载文本、数字或离散标签的传统 Excel/Markdown 式表格。
        
    - **区别点**：`grid_board` 强调空间邻近性，`table_matrix` 强调行列的数据对齐。
        
- **`node_link_graph` (拓扑节点网络图)**
    
    - **特点**：纯数学意义上的图论结构，由点（Nodes）和线（Edges）构成，布局是抽象的（拓扑意义大于绝对坐标）。
        
    - **对应渲染**：NetworkX, Graphviz.
        
- **`geometry_diagram` (几何矢量图)**
    
    - **特点**：由点、线、面、圆、多边形组成的 2 D 矢量几何图形，强调角度、面积和相交关系。
        
    - **对应渲染**：Matplotlib vector shapes, GeoGebra.
        
- **`chart_plot` (统计数据图表)**
    
    - **特点**：标准的科学或商业统计图表，包含坐标轴、刻度、图例。
        
    - **典型**：折线图、柱状图、散点图、雷达图、饼图。
        
- **`diagram_flow` (流程与概念结构图)**
    
    - **特点**：带有方向性箭头、文本框、层级关系的结构图，用以表达逻辑或时序流向。
        
    - **典型**：架构图、算法流程图、时序图、树状分类图。
        
- **`map_circuit` (物理拓扑图谱)**
    
    - **特点**：具有现实物理/工程意义的非抽象拓扑图。
        
    - **典型**：电路原理图（有标准的电阻/电容符号）、电子地图（有实际地理边界和路线限制）。
        
- **`symbol_panel` (符号/文字看板)**
    
    - **特点**：由纯文本、数学公式、ASCII 码字符、或者离散不规则符号组成的非网格化排列看板。
        
    - **典型**：火柴棍算式、七段数码管显示、纯符号矩阵。
        
- **`3d_projection` (三维投影/体素渲染)**
    
    - **特点**：使用透视或正交投影渲染的 3 D 物体、3 D 点云或体素（Voxel）网格。
        
    - **典型**：3 D Gaussian Splatting 的投影、CAD 模型、多视角立体图。
        
- **`scene_objects` (具象物体与自然场景)**
    
    - **特点**：包含现实世界具象物体（如天平、滑轮、日常物品）的摄影图像、或带有材质的 3 D 场景渲染。
        


## 针对你当前研究的额外建议 (第三轴：Environment/Rule Input)

由于你目前的工作和多模态大模型的训练、以及 RL（比如基于 `veRL` 等框架的 RLVR）有很深的交集，单纯的 **Reasoning $\times$ Visual** 只能描述“题目长什么样”。

在 RL 或自动化评估中，你可以引入第三轴：**`rule_delivery_mode` (规则交付方式)**：

1. **`implicit_zero_shot` (隐式/零知识)**：图片里不包含任何规则说明，模型必须拥有内置的先验（例如：模型必须本来就知道数独的规则、或者具备 ARC 的核心知识（Core Knowledge））。
    
2. **`explicit_text_prompt` (显式文本提示)**：在 Prompt 中用文字告诉模型环境规则（例如：“推箱子的规则是...，请给出下一步动作”）。
    
3. **`visual_demonstration` (视觉示例/Few-shot)**：通过给定的前几张图（In-context visual examples）让模型自己悟出规则（如 Raven/Bongard）。
